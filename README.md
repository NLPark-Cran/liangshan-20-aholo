## 这个仓库是什么

这是**黑客松参赛版**的完整前端。它与同项目的课程实践版是两个独立站点、两套页面，代码也不共用一份仓库。

## 怎么跑

纯静态，不需要构建，也没有运行时依赖。

```bash
cd site
python -m http.server 8080
```

然后打开 `http://127.0.0.1:8080/`。

必须走 HTTP 服务器，不能直接双击 `index.html`：页面用 ES module 和 `fetch` 加载数据与模型，`file://` 协议下会被浏览器的同源策略拦住。

### 后端是可选的

站点里所有 `/api/*` 请求都走 `js/api.js` 这一层。后端不可用时它会自动降级：`checkHealth()` 2.5 秒超时后把 `auth.online` 置为 `false`，登录、排行榜、结算提交这些功能静默关闭，三个玩法本身照常可玩。

也就是说，把 `site/` 单独部署到一个静态空间就能跑，不需要任何服务端。

## 3D 资产

13 件模型全部由 **Aholo Lux3D** 文生 3D 生成，其中三态山体是账本玩法的核心资产。

- `shan_healthy` 满山竹林，开矿前
- `shan_mined` 台阶矿坑，开采期
- `shan_restored` 重新复绿，关矿之后
- 其余 10 件对应长卷里的点位，由 `atlas.html` 按点位 id 动态加载

生成参数一致：`version G1`、`style photorealistic`、`faceCount 120000`、输出 `glb`。三态共用同一句收尾，以保证质感和收口方式统一。

原始 GLB 单件十几到二十几 MB，全部经 `gltf-transform` 压成 WebP 纹理加 meshopt 几何压缩后才入库，13 件合计 15.3 MB。运行时的 meshopt 解码器在 `vendor/three/libs/`。

> 已知瑕疵：满山竹林那一态的山顶留着一小块裸岩，与提示词写的「山顶圆润、竹冠连片」不符。做过一次重生成，接口返回成功但产物与第一版逐字节相同，模型没有实际改变。报告页里如实记了这一条。

## 数据

站里出现的数字都标了出处。每个数字必须能在调研记录里找到来源；引语逐字核对原文；本项目自撰的句子不伪装成引语。核不到的东西不写，也不写成估算值。

几处容易写错的口径，站内按核实结果处理：

- 云和梯田是「中国重要农业文化遗产」，当时仍在申报 GIAHS，不写「全球重要农业文化遗产」
- 钱江源在官方口径里仍是国家公园「候选区」
- 浦江水晶关停户数取「约 1.8 万家」，不取更早的「2 万余家」

`data/birds.js` 里每条记录都是一个观测事件：地点、时间、天气、鸟种、数量、记录人。稀有度按真实记录频率分级，不另造一套游戏稀有度。地名与鸟种的搭配必须真实。
